## 1. 执行摘要与定位

### 1.1 一句话定位

做一个「**全球多市场、多周期、可配置信号引擎 + 信号事后跟踪/回测统计**」的扫描网站：吸收 FlipScope「全市场扫描 + 极简列表 + 板块聚合」的长处，补上它没有的「**信号质量证据**」（延续率、MFE/MAE、双口径基准、扣费净期望、真实回测、样本外），并把现在聊天里推送的 5m EMA20 穿越扫描搬到网页上，解决图片刷屏和擦线噪音问题。

### 1.2 核心判断（结论先行）

| # | 判断 | 依据 |
|---|---|---|
| 1 | FlipScope 的算法本身很简单，护城河在「覆盖面 + 更新节奏 + UX + 社群」 | 调研 MD：fast=EMA(close,8)、slow=EMA(fast,13)，state 翻转即信号，无额外过滤（已拟合验证，误差 3e-7 级） |
| 2 | 它最大的短板是「没有真正的统计证据」 | 其「数据回测（30天内）」只是列出信号与信号价→现价涨跌，无胜率/盈亏比/回撤/净值 |
| 3 | 我们已有的 tracker 恰好补这块 | tracker.py 已实现每条信号 +15m/+30m/+1h/+2h/+4h 顺向收益、MFE/MAE、反穿判定、4h 结案、分组延续率 |
| 4 | 当前聊天推送模式已到瓶颈 | MT5 擦线约 90%；tracker 账本曾见单日数百条；截图一轮最多数十张 |
| 5 | 数据源是成本与合规的主变量，不是代码 | 加密公开 K 线免费；美股实时需付费；**对外公开展示/再分发行情通常需要商用授权（价格待询，见 §16.2）**；大陆公开收费另有牌照红线（第 14 节） |
| 6 | **算法无护城河，数据与账本才是**——point-in-time 名单 + 连续历史 K 线 + 前瞻跟踪账本无法事后补造 | 评审 S5；故 **M-1a 立即做内部快照与归档** |
| 7 | **「诚实度量」本身就是产品**：证据系统很可能证明「5m EMA 穿越扣费后 ≈ 随机」——这不是失败，是差异化的核心素材；我们公开参数哈希与成本模型，竞品通常不公开 | 评审 S1；审阅 O04 |
| 8 | 建议路线 | **M-1a 内部积累 →（你授权后）M-1b 外发试水 → M0/M1-lite → Gate-G → 再决定 M2/M3/开放收费** |
| 9 | 商业路径（已拍板） | 先自用跑通质量页；**尽早开放注册（免费档）**收集留存；有流量后再上付费档；收银可后置，账号/权限/套餐/计费接口与容量须预留 |

### 1.3 与 FlipScope 的差异化

| 维度 | FlipScope（事实） | 我们（计划） |
|---|---|---|
| 市场 | 美股 1000 / A 股 2001 / 加密 150 | 加密 + MT5（外汇/指数/商品/CFD）起步，后续美股/A 股/港股（对外展示受授权约束） |
| 周期 | 2h、「3 日」两档 | 5m/15m/1h/2h/4h/日/3 日，可配置；**加密 7×24** |
| 算法 | 固定 EMA8 × EMA13(EMA8) 交叉 | 可配置：EMA 价格穿越（M1-lite）、双 EMA 翻转对照（M1.5）、Supertrend；擦线、量能/ADX、多周期共振 |
| 更新 | 每 2 小时 | 按周期收盘触发（5m 级别 ≤ 2 分钟内出结果，目标值） |
| 数据清洗 | 2h 含盘前盘后稀疏 K 污染信号（事实） | 常规时段/成交量下限可选；缺口补拉；补不上跳过并告警 |
| 统计证据 | 无（只有 30 天信号列表） | 实时跟踪 + 结案统计 + **双口径 + 扣费净期望（含 funding）+ 置信区间声明** + 历史回测 + 样本外 |
| 图表 | K 线 + 量 + 一条均线 + 止损/入场 | 多面板（沿用现出图）；M1 静态 PNG，M1.5 交互；**不画入场/止损/目标** |
| 提醒 | 未见推送 | M1-lite：本聊天摘要+链接；**多渠道推送为 P2**（用户自选） |
| 交易建议 | 页面标「入场成本」「止损」 | **不标注入场/止损建议**；只显示双口径基准价（统计用） |
| **对无效信号的态度** | 不展示、不回答 | **正面展示**：「本策略在该分组扣费后无边际」也是有效结论 |
| **可审计性** | 参数/成本不透明 | **公开策略 params_hash、成本模型版本与样本口径** |

## 3. 竞品拆解：FlipScope（zhajixiong.com）

> 【事实】/【未公开】/【推断】标注规则同 v2；未出现在调研 MD 的内容不写。

### 3.1 功能清单（摘要）

登录（邮箱验证码）、信号监测 / 30 天「回测」列表 / 自选、美股≈1000 / A 股≈2001 / 加密≈150、周期 2h 与「3 日」、市值分档、每 2 小时更新、翻转后第 N 根状态、板块总览、详情图含入场/止损线、交流群一次性收费。**其「回测」无胜率/盈亏比/净值。**

### 3.2 信号算法（已拟合）

fast=EMA(close,8)；slow=EMA(fast,13)；state 变号即翻转；无额外过滤；入场=翻转 K 收盘；做多止损=翻转 K 最低。BTC 2h 相对误差 <1.3%（窗口截断种子差异）——对应我们要用固定锚点解决的问题（§6.1）。

### 3.3 启示

借鉴全市场扫描、板块聚合、翻转后第 N 根、邮箱验证码登录；不照搬入场/止损线与无统计证据；不用其私有接口；不纳入无公式指标。

## 6. 信号引擎规格

### 6.1 通用约定

| 项 | 规则 |
|---|---|
| 只用已收盘 K | close_time ≤ now |
| 时间 | 存 UTC，展示北京时间；K 以收盘时间标识 |
| 递归指标可复现性 | **固定锚点全量重算**：每品种每周期 `anchor_time`；禁止 300 根滑动截断；增量推进须与全量一致性测试通过 |
| EMA | alpha=2/(n+1)，adjust=False；预热 ≥ 3×N；不足预热不出信号 |
| K 线缺口 | 校验连续性→幂等补拉；**补不上：当轮跳过、不推进递归状态、标 stale、告警** |
| 服务器时区 | 每源 `server_tz_offset`（含 DST）；MT5 接入前用已知日线收盘对账（M1 完整版验收） |
| 指标版本 | 函数带版本号；变更后旧信号不自动重算，除非 `recompute` |
| 一致性测试三维 | ① vs 现脚本；② 同锚点不同窗口起点；③ 增量 vs 全量（若有增量）——进 CI |

### 6.2 策略 A：收盘价穿越 EMA(N)

| 项 | 定义 |
|---|---|
| 上穿 | close[i−1] ≤ EMA[i−1] 且 close[i] > EMA[i] |
| 下穿 | close[i−1] ≥ EMA[i−1] 且 close[i] < EMA[i] |
| 默认 | N=20；周期 5m；加密 7×24 |
| 附带字段 | EMA50、ST 方向、RSI14、MACD 柱、KDJ-J、VolMA20 比、ATR14/price 波动率档（展示/分组，不改信号） |

### 6.3 策略 B：双 EMA 翻转（P1）

| 项 | 定义 |
|---|---|
| B1 FlipScope 对照 | fast=EMA(close,8)；slow=EMA(fast,13)；state 变号 |
| B2 普通双均线 | EMA(close,a) vs EMA(close,b) |
| 展示 | 翻转 K 收盘作口径 A 之一；不显示止损 |

### 6.4 策略 C：Supertrend 翻转（P1）

ATR10（Wilder RMA）×3；dir 变号即信号。

### 6.5 擦线与过滤器

| 过滤器 | 定义 | 默认 | 作用 |
|---|---|---|---|
| 擦线 % | \|close−EMA\|/EMA < θ | θ=0.05% | 打标；列表默认隐藏 |
| 擦线 ATR | \|close−EMA\| < k×ATR14 | k=0.1（待回测） | 跨资产更公平 |
| 量能 | volume ≥ m×VolMA20 | 加密可开；**MT5/CFD 默认关**（tick_volume ≠ 真实成交量，不可跨品种比） | 降假突破 |
| ADX | ADX14 ≥ a | a=20 | 降横盘 |
| 间距 | \|fast−slow\| ≥ g×ATR14（策略 B） | g=0.1 | 降缠绕 |
| 稀疏 K | volume < 近 20 日同时段中位数 ×10% | 美股/港股默认开 | 降盘前盘后污染 |
| 冷却 | M 根内反向标「来回」/whipsaw | M=3 | 主统计单列 |
| 多周期共振 | 与高一级周期 EMA 状态同向 | 仅打标 | 筛选 |
| 波动率档 | ATR14/price 30 日三分位 | 仅分组 | 制度差异 |

> 默认值是起点；以回测样本外为准并在页面公开。参数平原规则（邻域 ±20% 降幅 <30%）为**启发式**，须在报告中标注可被样本外推翻。

### 6.6 周期聚合规则（见 D9）

| 市场 | 2h | 日 | 3 日 |
|---|---|---|---|
| 加密 | 币安原生 2h（UTC 偶数整点） | UTC 00:00 | 每 3 自然日，锚点固定 |
| 美股 | RTH 四段；默认不含盘前盘后 | 交易日 RTH | 每 3 交易日 |
| A 股 | 9:30–11:30、13:00–15:00 | 交易日 | 每 3 交易日 |
| MT5 | 经 server_tz 转换后聚合 | 服务器日 | 每 3 交易日 |

## 7. 信号跟踪、延续统计与真实回测规格

### 7.1 前瞻跟踪（双口径 + 边界）

| 字段/规则 | 定义 |
|---|---|
| 口径 A `ref_close` | 信号 K 收盘价 |
| 口径 B `ref_next_open` | **同一 timeframe 下一根已收盘 K 的 open** |
| 无次根 | 若结案窗结束仍无次根 → `baseline_unavailable=true`，**口径 B 不参与净期望分子/分母**（口径 A 仍可统计）；页面显示「口径 B 不可用」 |
| 顺向收益 | 上穿：(价−基准)/基准；下穿：(基准−价)/基准；两口径分算 |
| 节点 | 5m：+15m/+30m/+1h/+2h/+4h；取首根收盘时间 ≥ 节点的收盘价 |
| MFE/MAE | 窗内最大顺向 / 最大逆向 |
| 反穿 | 任一根收盘回到 EMA 另一侧 |
| 结案 | 满窗冻结；**品种下架/长期 stale：强制结案，`ended_reason=delisted\|stale`** |
| 加密价格类型 | 默认与现脚本一致用 **last 价 K 线**；若改 mark 价须新 `params_hash` |
| 展示默认 | **页面与推送默认口径 B**；A 并列 |

### 7.2 统计输出

| 维度 | 内容 |
|---|---|
| 分组 | 市场、类别、周期、策略、方向、擦线/实穿、共振、时段、星期、波动率档 |
| 指标 | 样本数、各节点顺向>0 占比、平均/中位顺向（双口径）、MFE/MAE、反穿率、结案延续率、**净期望 = 平均顺向(口径B) − (fee+slip+funding 往返)** |
| 可信度 | n<30 灰显并排除「优于基线」；Wilson 95% CI；**页面声明：CI 未校正同品种短时相关（完整 block bootstrap 为 P1）**；whipsaw 单列 |
| 多重检验 | 展示「共检验 N 分组」；P1 对「优于基线」做 BH-FDR |
| 结论原则 | 净期望 ≤0 且 CI 含 0 → 标注「无统计边际」 |

## 9. 系统架构

### 9.1 逻辑架构

```
Collectors: binance_rest / coingecko_universe / mt5_bridge / (alpaca|tushare|futu 后续)
    → 幂等 upsert + 血缘 + 缺口检测
Storage: Postgres + TimescaleDB
    bars / universe_snapshots / signals / tracks / stats_daily / users / plans / entitlements
Engine: 固定锚点重算 → 策略 → 过滤 → 去重 → tracker → 预聚合
    CLI: backfill / recompute
API: FastAPI（REST + 可选 SSE；可降级轮询）
Notifier: 本聊天（P0）；多渠道插件（P2）
Front: Next.js（M1 静态 PNG；M1.5 交互图）
Obs: /health + Prometheus 指标（Grafana 可后置）；Uptime 拨测；对象存储备份
```

### 9.2 技术选型

| 层 | 选型 | 注意 |
|---|---|---|
| 计算 | Python 3.12 + pandas/numpy | 复用现脚本 |
| 调度 | APScheduler/cron；**加密 7×24 按 5m 收盘 +N 秒**；MT5 可仍 08–23 | `exchange_calendars`；DST 单测 |
| 存储 | PG16 + Timescale | 压缩与保留策略见 §13 |
| API | FastAPI | SSE 需常驻；托管 Serverless 时改轮询 |
| 前端 | Next.js | M1 PNG；M1.5 lightweight-charts（保留署名） |
| 认证 | 托管认证优先（Supabase Auth / Clerk） | 开放注册路径 |
| 计费 | BillingProvider stub → MoR | 收银后置 |
| 部署 | Docker Compose 起步 → 可水平扩 API/worker | 见 §9.4 容量 |

### 9.3 部署选项
