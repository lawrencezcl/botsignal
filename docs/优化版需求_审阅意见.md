## 1. 总体评价

v2 把 v1 里偏「功能清单」的草稿，收成了一份可验收、可止损的工程规格：固定锚点全量重算（§6.1）、双口径基准与扣费净期望（§7.1–7.2）、point-in-time universe（F-M8）、`backfill`/`recompute` 升 P0（F-D4）、418 熔断（§8.1 / R2）、M-1→M1-lite→Gate-G 验证路线（§15）都是对现网痛点（擦线约九成、聊天刷屏、窗口漂移、电脑离线断 MT5）的正确回应。与今日 tracker 实况对照也站得住：币安擦线约 37%、MT5 擦线约 90%，且截至写审阅时仍无满 4h 结案样本——「证据诚实优先于信号好看」（文首原则 / R12）不是口号，是当前数据已经在逼近的结论。

仍需再收一刀的，主要不是「缺功能」，而是：**（1）文内自相矛盾（尤其 M-1「立即启动」vs「确认前不开发」、F-S2 标 P0 却放 M1.5）；（2）Gate-G 验收可测性不足（条数门槛未区分擦线/实穿，也未绑定扣费后净期望）；（3）成本模型与数据依赖相对实盘还有缺口（资金费率、CoinGecko、加密 24×7 调度）；（4）M1-lite 工期打包偏乐观。** 建议把下列「必须改」合入 v2.1 后再让你对第 18 节拍板；M-1 里可立即做的只保留**可逆、内部、无外发**的数据积累，外发周报/落地页须你显式授权。
